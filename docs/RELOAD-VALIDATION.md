# Sponge 12 维度热重载验证

## 结论

SpongeNeo 12.0.4-RC0 / Minecraft 1.21.1 支持在完整卸载一个非默认维度后，替换其
磁盘目录，再以相同 world key 加载新实例。连续 3 轮自动化测试均成功：

- 卸载耗时约 43–57 ms
- 包含保存、卸载、目录备份、脏数据校验、恢复和重载的完整流程约 1.6–2.9 s
- 没有出现旧 `ServerWorld` 实例被复用、文件占用、重复注册失败或挂起

这并不是“保持维度运行的同时原地热替换”。安全边界是：

1. 世界内玩家必须为零。
2. 必须调用 `saveAndFlush()`。
3. 必须等待 `WorldManager.unloadWorld()` 完成，并确认
   `WorldManager.world(key)` 为空。
4. 才允许替换维度目录。
5. 最后以同一 key 重新加载。

默认主世界不能被卸载或以同一方式替换。

## 实测流程

测试插件在专用维度放置玻璃标记，然后执行：

1. 保存、卸载并备份干净目录。
2. 加载并改成泥土，再保存卸载。
3. 重新加载，确认泥土已落盘。
4. 再次卸载，用玻璃备份替换整个维度目录。
5. 用同一 `multiworldplatform:*` / 测试命名空间的 key 加载。
6. 读取标记，确认恢复成玻璃。

测试日志位于测试服务端：

`run-test-server/logs/latest.log`

## 对地图恢复插件的影响

小游戏插件可以实现“保存地图快照、清空玩家、卸载、恢复目录、同 key 重载”的流程，
通常不需要另一个世界管理器插件。额外依赖只在需要以下能力时才有价值：

- 跨机器备份/对象存储
- 事务回滚和校验和
- 多个地图并发排队
- 自定义可序列化 `ChunkGenerator`
- 服务器级 generate-structures 的跨平台定制

MultiWorldPlatform 已把世界操作串行化、把玩家转移到安全世界，并提供 ZIP 导入导出，
可直接作为小游戏插件的底层实现或参考实现。

## 不建议的做法

- 在维度仍加载时删除或覆盖其 region/data 文件
- 未保存就卸载
- 世界仍有玩家时强行卸载
- 先删除旧目录、再试图把旧 `ServerWorld` 对象继续使用
- 在服务器主线程调用异步 future 的 `join()`/`get()`
